# Babuni Gaming repository instructions

Read [README.md](README.md) and [docs/CONTENT.md](docs/CONTENT.md) before editing. Preserve the project scope, supplied profile URLs, artwork credit, and published module IDs.

Write development and project narratives in Babuni's first-person voice. Vary sentence openings and avoid starting a sentence with “I” or “My.” Use “creative” as the role label. Babuni is the person, Babuni Gaming is the project, and babuni.dev is the portfolio. Use neutral factual language in changelog entries and technical reference.

Credit the human creative's decisions and AI work accurately. Name the AI tool and verified model when available. State when either was not recorded. Preserve distinctions between planned work, actual changes, and verified results.

## Human–AI collaboration record

`docs/AI_COLLABORATION.md` is the short record of how Babuni works with AI and who did what, with the same text in all of Babuni's repositories. Do not add dated entries, session notes or per-change attribution to it. Record each contribution in `docs/DEVLOG.md` (what Babuni asked for and what the AI did, naming the tool and model) and in `CHANGELOG.md`. Change `docs/AI_COLLABORATION.md` only to add a row to its "Who did what" table when a new AI tool or model starts contributing to this project, or when Babuni revises the shared text.
